# 4-DOF Robotic Arm — ROS 2, Gazebo & Custom PID Control

A compact robotics project demonstrating modelling, simulation, controller integration, and closed-loop trajectory tracking for a **4-DOF serial robotic arm** using **ROS 2 Humble**, **Gazebo Fortress**, and **ros2_control**.

## Project objective

The goal was to build a simulated robotic arm from the URDF level upward, connect it to `ros2_control`, implement a custom **effort-based PID controller**, and evaluate how accurately each joint follows a sinusoidal reference trajectory.

The project progressed from basic position control to a custom torque / effort controller, followed by iterative PID tuning based on measured tracking error and recorded joint trajectories.

## System overview

| Component | Implementation |
|---|---|
| Robot model | 4-DOF serial manipulator in URDF/Xacro |
| Simulation | Gazebo Fortress / Ignition Gazebo 6 |
| Middleware | ROS 2 Humble |
| Control interface | `ros2_control` with position and effort interfaces |
| Baseline controller | `joint_trajectory_controller/JointTrajectoryController` |
| Custom controller | C++ PID node publishing joint efforts |
| Effort interface | `effort_controllers/JointGroupEffortController` |
| Feedback | `/joint_states` |
| Reference logging | `/desired_joint_states` |
| Evaluation | Desired-vs-actual plots and RMSE |

## Control architecture

```text
Sinusoidal joint reference
        |
        v
Custom C++ PID controller
        |
        |  joint torque / effort commands
        v
/effort_controller/commands
        |
        v
Gazebo + ros2_control
        |
        v
/joint_states
        |
        +-----------------------> PID feedback
```

For each joint, the controller computes

```text
error = q_desired - q_actual

tau = Kp * error
    + Ki * integral(error)
    + Kd * (qdot_desired - qdot_actual)
```

Torque saturation and integral anti-windup are included to keep the simulation stable.

## Reference trajectory

The final evaluation uses a **joint-space sinusoidal trajectory** with frequency

```text
f = 0.08 Hz
T = 1/f = 12.5 s
```

The commanded joint positions are

```text
q1(t) =  0.35 sin(2*pi*0.08*t)
q2(t) =  0.25 sin(2*pi*0.08*t)
q3(t) = -0.20 sin(2*pi*0.08*t)
q4(t) =  0.15 sin(2*pi*0.08*t)
```

| Joint | Amplitude [rad] | Approx. amplitude [deg] |
|---|---:|---:|
| Joint 1 | 0.35 | 20.1° |
| Joint 2 | 0.25 | 14.3° |
| Joint 3 | -0.20 | -11.5° |
| Joint 4 | 0.15 | 8.6° |

## Final PID configuration

| Joint | Kp | Ki | Kd | Torque limit [Nm] |
|---|---:|---:|---:|---:|
| Joint 1 | 6.0 | 0.10 | 1.2 | 8.0 |
| Joint 2 | 20.0 | 0.00 | 5.0 | 10.0 |
| Joint 3 | 14.0 | 0.30 | 1.8 | 10.0 |
| Joint 4 | 7.0 | 0.10 | 1.0 | 6.0 |

Joint 2 required the most tuning because it showed a strong over-response under effort control. Removing its integral term, increasing damping, and limiting torque significantly improved its tracking.

## Final tracking results

RMSE was calculated from the recorded desired and measured joint positions.

| Joint | RMSE [rad] | RMSE [deg] |
|---|---:|---:|
| Joint 1 | **0.0290** | **1.66°** |
| Joint 2 | **0.0890** | **5.10°** |
| Joint 3 | **0.0585** | **3.35°** |
| Joint 4 | **0.0649** | **3.72°** |

The final controller is stable on all four joints, with particularly strong tracking on Joint 1 and a major improvement in Joint 2 compared with the earlier tuning iterations.

## Engineering challenges solved

- Built a multi-link 4-DOF arm using URDF/Xacro.
- Added inertial, collision, joint-limit, and `ros2_control` definitions.
- Integrated Gazebo with ROS 2 controllers.
- Added separate position and effort command interfaces.
- Anchored the robot base to the Gazebo world for stable effort-control experiments.
- Implemented a custom C++ closed-loop PID controller.
- Added torque saturation and integral anti-windup.
- Diagnosed conflicting desired-state publishers that contaminated early logging results.
- Tuned the controller joint-by-joint using measured RMSE and desired-vs-actual plots.
- Reduced Joint 2 RMSE from severe over-response to **0.089 rad** in the final run.

## Running the simulation

```bash
source /opt/ros/humble/setup.bash
source ~/samarth_arm_ws/install/setup.bash
export FASTDDS_BUILTIN_TRANSPORTS=UDPv4
ros2 launch samarth_arm_control simulation.launch.py
```

Start the custom PID controller:

```bash
ros2 run samarth_arm_control pid_controller
```

Switch from position control to effort control:

```bash
ros2 control switch_controllers \
  --deactivate arm_controller \
  --activate effort_controller
```

Record tracking data:

```bash
ros2 run samarth_arm_control joint_logger.py
```

## What I learned

This project gave me hands-on experience with the complete robotics control pipeline: robot modelling, simulation, ROS 2 communication, controller-manager configuration, effort control, feedback control, debugging, experimental logging, and quantitative controller tuning.

A key lesson was that stable control is not achieved by simply increasing gains. The final improvement came from understanding the shape of the tracking error, isolating each joint's behaviour, reducing unnecessary integral action, adding damping, and limiting actuator effort.
